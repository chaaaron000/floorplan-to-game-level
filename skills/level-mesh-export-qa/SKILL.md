# level-mesh-export-qa

정적 레벨 형상을 게임용 FBX로 내보내고 검수하는 단계의 규칙이다. 형상의 **입력**이 평면도라면 그 전에 `floorplan-trace` 스킬로 형상을 만들고 평면과 대조한다. 여기서 아무리 정밀해도 틀린 평면은 틀린 채로 나간다.

## 순서

1. **대상 엔진을 사용자에게 묻는다: Unity / Unreal / 둘 다.** 저장소에 한쪽 엔진 프로젝트만 보여도 묻는다. 답과 날짜를 내보내기 폴더의 `README`(없으면 작업 메모)에 적고, 고른 엔진의 파일만 읽는다: [`engines/unity.md`](engines/unity.md), [`engines/unreal.md`](engines/unreal.md). 축·단위, 표식을 어디에 두는지, 충돌 메시를 엔진이 어떻게 받는지가 여기서 갈린다.
2. **시작 전 점검**(아래)을 한다.
3. **합치고 내보낸다.** 아래 합치기 규칙과 엔진 파일의 내보내기 규약을 따른다.
4. **검사한다.** `checks/run_all.py`를 내보낸 FBX에 돌려 `validation_*.json`을 남긴다. 끝난 기준: 아래 검사 목록의 모든 줄이 `passed` 참/거짓으로 남았고, `not_run`에 남은 검사마다 돌리지 않은 이유가 보고에 있다.
5. **엔진 임포트 검수**를 엔진 파일의 목록대로 한다.
6. **렌더를 직접 연다**: 평면 겹침, 조감, 실내 3~4장, 모서리·T 접합 확대, 보행 격자 그림. 카메라가 벽 안에 있거나 흰 벽만 보이면 다시 찍는다.
7. **보고한다**(아래 보고 규칙).

## 시작 전 점검

- 지금 열린 Blender 파일에 저장 안 된 변경(`bpy.data.is_dirty`)이 있으면 그대로 두고 먼저 보고한다. 다른 작업자의 결과일 수 있다.
- 생성·내보내기 스크립트는 기존 결과물이 있으면 멈추게 만들고, 덮어쓰기는 명시적 인자(`--force` 등)로만 한다.
- 무겁거나 크래시 위험이 있는 검사(IDS·BCF 보고서, 대량 테셀레이션, 이 스킬의 `checks/`)는 백그라운드 Blender(`blender -b --python ...`)에서 돌린다. `ifctester`에 넘기는 IFC 파일 객체는 변수에 잡아 둔다(임시 객체를 넘기면 보고서가 해제된 파일을 읽다 Blender가 죽는다).
- 긴 렌더·검사는 MCP 응답 제한에 걸리므로 백그라운드로 돌리고 결과 파일로 완료를 확인한다.

## 합치기 규칙

- 정적 요소는 재질·구성 요소별로 한 메시(벽, 바닥, 천장, 창틀, 유리, 수납 등). 문짝은 문짝마다 독립 메시이고 피벗은 경첩이다.
- 충돌 메시는 `COL_` 접두어의 닫힌 메시다(정적 지형, 문짝마다 하나). 표식은 `DOOR_...`/`ROOM_...` 이름을 쓴다. 표식을 FBX 안의 empty로 둘지 별도 파일로 둘지는 엔진 파일을 따른다.
- 합칠 때는 정확한 솔리드 연산을 쓰고 재질 출처를 유지한다. 합친 뒤 내부 면이 없어야 한다.
- Blender·FBX는 float32다. **float32로 다시 만든 다음에** 재질 경계를 나누고 검사한다. float64에서만 맞는 형상은 내보낸 뒤 틈이나 면적 0 면이 생긴다. `checks/`가 FBX를 다시 들여와 검사하는 것도 같은 이유다.
- 맞닿은 요소를 몇 mm 부풀려 억지로 겹치게 하는 방식은 최후 수단이다. 썼다면 대상·양·남은 겹침을 보고한다.
- 모든 렌더 메시에 UV 두 채널(둘째가 라이트맵용). 단위 미터, 층 바닥 윗면 Z=0, 축·스케일 적용(객체 스케일 1).
- 방 표식은 그 방 안에서 캐릭터가 설 수 있는 바닥 위에 둔다(가구 위·벽 속이 아니다). 붙박이로 가득 찬 공간은 앞 바닥에, 바닥이 뚫린 공간(승강로·샤프트)은 `floor_kind=void`로 표시한다.

## 검사 목록

결과는 `validation_*.json`에 **잰 수치**로 남기고, 하나라도 기준을 넘으면 `passed: false`다. 통과를 가정하지 않는다. 돌리지 못한 검사는 통과가 아니라 `not_run`이다.

| 검사 | 기준 | 스크립트(`checks/`) |
|---|---|---|
| FBX 재임포트 | 빈 Blender에 다시 들여와 이름·개수·스케일 1·월드 경계(0.1mm)·삼각형·UV2·재질이 manifest(없으면 기대 개수)와 일치 | `check_fbx_roundtrip.py` |
| 비매니폴드 엣지 | 닫혀야 하는 메시(모든 COL, 닫힌 렌더 메시)에서 0. 재질 경계에서 열어 둔 렌더 메시는 용접 합본의 열린 가장자리 0 | `check_mesh_topology.py` |
| 면적 0 면 | 0. **삼각화한 뒤** 삼각형마다 국소 좌표 float64 외적으로 잰다(전역 좌표 float 면적은 얇은 삼각형에서 상쇄된다) | 〃 |
| 뒤집힌 셸 | 0. 합친 고체 안의 빈 공간 셸과 두께 0 조각은 수를 보고한다 | 〃 |
| UV2 | 모든 렌더 메시에 2채널 | 〃 |
| 서로 파고듦 | 경계 상자가 겹치는 쌍마다 교차 부피 > 1e-7 m³가 0쌍 | `check_interpenetration.py` |
| z-fighting | 같은 방향·같은 평면(1°, 2mm)에서 겹친 넓이 > 1cm²가 0쌍 | `check_zfighting.py` |
| 떠 있음 | 벽·기둥·수납 섬의 바닥이 바닥에서 1cm 이상 뜬 것 0 | `check_floating.py` |

| 천장고 | 바닥 있는 모든 `ROOM_` 표식에서 위로 쏜 광선이 기대 천장고 ±2mm | `check_ceiling_height.py` |
| 단면 형상 | 벽·바닥판 셸을 수평으로 잘라(벽은 바닥 위 0.15m와 1.2m) `short_segment`·`wall_jog`·`near_axis_skew`·`irregular_curve` 0. 창틀·문틀·유리는 빼고 본다 | `check_section_shape.py`(`mesh_shape_qa.py`) |
| 도달 가능성 | 시작점(계단실·승강기 홀)에서 캡슐로 걸어서 모든 방 표식과 통로 문에 닿는다. 층을 쌓았을 때 위·아래 층과 이어진다 | `check_reachability.py` |
| 문 최대 열림 | 닫힌 채 고정 지형과 겹친 문짝 0. 최대로 연 채 남는 통과 폭이 캡슐 지름 이상(통로 문) | `check_door_swing.py` |
| 원본 재열기 | 저장한 IFC를 다시 열어 모든 형상이 테셀레이션됨(IFC 원본일 때) | `check_ifc_reopen.py` |
| 엔진 임포트 | 엔진 파일의 목록 | `engines/*.md` |
| 평면 대비 | 모델 바닥 투영을 원본 평면에 색 겹침 | `floorplan-trace`의 `plan_overlay_<층>.png`·`plan_diff_<층>.png` |
| 렌더 | 직접 열어 본다(순서 6) | — |

의도된 예외는 수치와 이유를 함께 남긴다(예: "재질 분할 메시의 열린 경계 1,160은 재질 경계. 용접 합본은 열린 가장자리 0").

단면 형상 검사는 형상을 어떻게 만들었든 결과 메시만 본다. 원본 겹침이 맞아도 픽셀 윤곽으로 만든 벽은 여기서 걸린다(예시: 픽셀 윤곽에서 뽑은 벽을 z 1.2m에서 자르니 644변 중 5cm 미만이 132, 짧은 변 131·비틀림 122·턱 33·불규칙 곡선 5). 걸리면 메시를 고치지 말고 `floorplan-trace`의 추적 파일로 돌아가 그 벽의 가장자리 값을 다시 잰다. 실제 사선은 `--shape-directions`로 주고, 실제 단차는 수치와 근거를 보고에 적는다.

## 검사 스크립트(`checks/`)

Blender 파이썬에서 돈다(FBX 임포터·BVH·Boolean을 쓴다). `numpy`는 Blender에 들어 있고, `shapely` 2.x가 Blender 파이썬에 있어야 한다(z-fighting·접합 틈·문 열림). 보행 격자 그림은 `PIL`, IFC 재열기는 `ifcopenshell`을 쓴다. 없으면 설치를 사용자에게 알리고, 못 돌린 검사는 `not_run`으로 보고한다.

```
blender -b --factory-startup --python <이 스킬>/checks/run_all.py -- \
    --fbx <level.fbx> [--manifest <manifest.json>] --out <validation.json> \
    --floating-objects "<벽·기둥·수납 메시 정규식>" --gap-objects "<벽·기둥·유리·창틀 정규식>" --shape-objects "<벽 정규식>" \
    --capsule-radius <m> --capsule-height <m> --step-height <m> --seed-marker <시작 표식> \
    [--stack=-1,0,1 --pitch <층 높이>] [--nav-png nav.png] [--min-clear-width <캡슐 지름> --door-require access=passage]
```

- 입력은 `--fbx`(빈 씬에 다시 들여온 float32 메시)가 기본이다. `blender -b <파일.blend> --python ... -- --scene <씬>`으로 열린 씬을 볼 수도 있지만, 내보낸 결과의 판정은 FBX로 한다.
- 표식은 `--manifest`가 있으면 그 JSON에서, 없으면 FBX 안의 empty(이름 접두어 + 커스텀 속성)에서 읽는다. 어느 쪽인지는 엔진 파일이 정한다.
- 대상 메시는 이름 정규식으로 고른다. 고르지 않은 검사(떠 있음·접합 틈·단면 형상)와 캡슐 값이 없는 도달 가능성은 돌지 않는다. **캡슐 반지름·높이·단 높이는 게임의 캐릭터·내비 설정에서 가져온다**(엔진 파일에 어디서 읽는지 있다). 값을 지어내지 않는다.
- 검사 하나만 다시 돌릴 때는 `--only reachability,door_swing`처럼 고르거나 `check_*.py`를 직접 부른다. 인자와 판정 규칙은 각 파일 머리말에 있다.
- 걸리는 시간(예시): 메시 156개·삼각형 1.8만 개 한 층에 약 50초. 대부분 교차 부피다.

결과를 읽을 때:

- **교차 부피**: FBX는 float32라 맞닿기만 한 면에서도 (맞닿은 넓이 × 약 1µm)의 부피가 나온다. 기준 근처 값은 그 크기와 견줘 읽는다. 기준을 넘은 쌍은 순서를 바꿔 다시 잰 두 값이 함께 남는다.
- **접합 틈**: 관통 틈(`gap`)만 판정한다. 한쪽이 막힌 턱(`notch`), 갇힌 빈틈(`cavity`), 폭 0.1mm 미만 실금(`hairline`)은 수치로 보고한다.
- **도달 가능성**: 문 통과는 표식 중심의 (폭 × 깊이) 띠에 시작 성분의 칸이 있는지로 본다. 깊이는 표식의 `depth_m`(없으면 0.10m)이라, 벽이 두꺼운 문은 `depth_m`을 넣어 준다. 문짝은 장애물에 넣지 않는다. 끊긴 성분이 조리대 윗면 같은 곳인지 `--nav-png` 그림으로 확인한다.
- **문 최대 열림**: 문 표식에 `hinges_world_json`·`swing`이 있어야 돈다. 평면에서 문짝 상자(조금 줄인 것)를 돌려 고정 지형 단면과 겹치기 직전의 각이다. 엔진 쪽 문 검사가 있으면 `--swing-shrink`를 그 값에 맞춘다. 구한 각을 manifest에 넣을지는 프로젝트가 정한다(`engines/unreal.md`의 프로젝트별 확장).

## 보고 규칙

- 측정하지 않은 값을 측정값처럼 쓰지 않는다. 재질 슬롯 수는 드로콜 측정값이 아니다.
- 비교하지 않은 이전 결과와의 우열을 주장하지 않는다.
- 남은 문제는 수치로(예: "문턱 겹침 3.4mm 1건, 창틀 면적 0 삼각형 64개"). 고치지 않은 이유를 함께 적는다.
- 대상 엔진(1번의 답), 재생성 명령과 걸린 시간, 만든 파일 목록, 원본 대비 메시·삼각형 수, `not_run` 검사와 이유.
