# floorplan-trace

평면을 **읽고**, 읽은 벽을 **재고**, 잰 값을 추적 파일에 **적는다.** 형상의 출처는 추적 파일 하나이고, 그 벽 목록은 작업자가 쓴다. 공용 빌더가 추적 파일에서 IFC, 게임 메시, 검사 결과, 평면 겹침 그림을 만든다.

측정 도구는 정한 벽의 좌표를 얻는 데 쓴다. 띠 검출·윤곽 추출·PDF 벡터 도형 같은 자동 추출 결과를 벽 목록으로 옮기지 않는다. 무엇이 벽인지는 읽어서 정한다.

## 도구와 참고 자료

| 파일 | 쓰는 때 |
|---|---|
| `plan_tools.py` | 렌더링, 좌표 격자 타일·크롭, 벽 띠 재기, 원 맞춤, 축척 대조, 층 맞춤. 명령과 인자는 `python plan_tools.py -h` |
| `plan_build.py` | 추적 파일 → IFC·blend·`validation.json`·겹침 그림·렌더 |
| [references/trace_template.py](references/trace_template.py) | 추적 파일과 프로젝트 정의의 틀. 표마다 문법이 주석으로 있다 |
| [references/plan_build.md](references/plan_build.md) | 빌더가 각 표를 어떻게 쓰는지, 검사 항목의 뜻, 겹침 그림의 색 |
| [references/symbols.md](references/symbols.md) | 문·창·샤프트·수납 기호를 읽을 때 |
| [references/families.md](references/families.md) | 도면 계열별 주의점(벽 색, 워터마크, 축척 근거, 층마다 다른 평면 위치) |

예시 입력은 `tests/`(축척 근거 `scale.json`, 출처 `source.json`)와 `references/trace_template.py`에 있다.

## 절차

각 단계의 완료 기준을 채운 뒤 다음 단계로 간다. 한 작업은 한 작업자가 한 컨텍스트에서 끝까지 한다.

1. **그림 준비.** PDF는 `render`로 평면 영역만 렌더링한다. 가장 얇은 벽 띠가 6px 이상 되는 해상도를 고르고, 벽과 겹치는 워터마크 글자는 지운다. 원본 그림은 `refs/floorplans/<건물>/`(git 제외)에 두고 추적 파일의 `IMAGE`가 그 경로를 가리킨다. 측정용 타일·크롭·스크립트와 축척 근거 파일은 그 아래 `work/`에 둔다.
   - 완료 기준: 층마다 그림 한 장과 렌더링 설정(쪽, dpi, clip)이 있다.
2. **축척.** 근거를 두 종류 이상 모아 `scale`로 대조한다: 축척 막대(`pdfbars`), 방 치수(`pdfdims` 글자 위치에서 벽 안쪽 면 사이를 잰 값), 면적표. 근거 파일 형식은 `tests/*/scale.json`.
   - 서로 허용 오차 안이면 그 값을 쓴다. 맞지 않거나 가로·세로 축척이 4% 넘게 다르면 어느 값을 썼는지와 이유를 추적 파일 머리말과 보고에 적는다.
   - 완료 기준: 축척(m/px), 근거 목록, `scale` 결과가 추적 파일 머리말에 있다.
3. **읽기.** `tiles`와 `crop`으로 좌표 격자가 그려진 확대 그림을 만들어 평면 전체를 빠짐없이 연다. 벽·문·기둥·코어·계단·유리·붙박이를 하나씩 식별하고 이름을 붙인다. 채움 색이 같은 것(벽, 기둥, 세대 밖 면)은 읽어서 가른다.
   - 완료 기준: 평면의 닫힌 영역마다 이름과 종류(방, 수납, 샤프트, 계단실, 승강로, 테라스, 아래로 열린 곳)가 정해졌다.
4. **재기.** 식별한 벽마다 **원본 해상도의 픽셀**에서 벽 띠의 시작과 끝을 잰다(`runs`, 또는 직접 짠 측정 코드). 문은 띠가 끊긴 구간의 시작과 끝이다. 유리선은 안·밖 두 줄을 여러 곳에서 재서 직선을 맞춘다. 곡선은 선 위의 점을 모아 원을 맞추고 잔차를 본다(`arc`, 잔차 1px 안팎). 축에 맞지 않는 벽은 띠 위 여러 점으로 직선을 맞춘다.
   - 완료 기준: 추적 파일에 적을 좌표가 모두 원본 픽셀에서 잰 값이거나 그 값에서 계산한 값이다.
5. **적기.** `references/trace_template.py`를 복사해 층마다 추적 파일 하나, 그리고 `project.py` 하나를 쓴다.
   - 벽은 가장자리를 잰 사각형이다. 맞닿는 벽은 같은 픽셀 값을 쓰고, 면으로 닿거나 겹치게 적는다.
   - 벽은 문 구간을 가로질러 이어서 적는다.
   - 두께가 제각각인 코어와 칠해진 덩어리는 평면의 채움 그대로 사각형 여러 개를 겹쳐 적는다.
   - 머리말에 측정 방법과 평면에 없어 정한 값을 적는다.
   - 완료 기준: 3단계에서 식별한 것이 모두 추적 파일에 있다.
6. **빌드.** 추적을 고치는 동안은 `--no-render`로 돌린다.
   ```
   "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --python .claude/skills/floorplan-trace/plan_build.py -- <project.py> --no-render
   ```
   - 완료 기준: 끝에 `PROBLEMS 0`이 찍힌다.
7. **평면과 대조.** 층마다 `renders/plan_overlay_<층>.png`와 `plan_diff_<층>.png`를 직접 연다. 차이 그림의 빨강(평면에만 있는 벽)과 파랑(모델에만 있는 벽) 덩어리를 하나씩 본다. 추적 파일을 고치고 6단계로 돌아가거나, 그대로 두는 이유를 적는다. 문 구간과 글자 자리는 남는 것이 정상이다.
   - 완료 기준: 남은 덩어리마다 고쳤거나 이유가 있다. `validation.json`의 층별 `plan_match.iou`를 적었다.
8. **렌더와 보고.** 옵션 없이 전체 빌드를 돌리고 조감과 실내 컷을 직접 열어 평면과 같은 공간인지 본다. 보고에 다음을 적는다.
   - 읽기가 갈릴 수 있는 해석(이름 없는 방, 채움 면의 정체, 문 종류)
   - 평면에 없어 정한 값(높이, 깊이, 난간, 계단 단 수)
   - 층 사이에 실제로 다른 것(기둥·유리·코어 위치)
   - `validation.json`의 일치도, 틈, 메시 수치

## 여러 층

- 층마다 자기 그림의 픽셀로 적는다. 층마다 그림의 위치와 배율이 다를 수 있다(0.3~0.6% 차이가 있었다).
- 층마다 그대로 남는 것(승강로, 계단실, 코어 벽 면, 기둥)을 두 그림에서 재서 쌍을 만들고 `fitalign`으로 배율과 이동을 맞춘다. 결과를 `TO_REF` 또는 `FROM_REF`로 적는다. `align`은 대략의 이동을 먼저 찾을 때 쓴다.
- 위아래로 같은 벽은 `SNAP_TO_BELOW_PX`로 아래층 가장자리에 맞춘다. 평면이 층마다 실제로 다른 곳(기울어진 기둥, 물러나는 외곽)은 그 층 그림대로 적고 `vertical_alignment` 수치와 함께 보고한다.
